# herdr-dock-grid 개선 TODO

`herdr-dock-grid`를 2x2 pane 배치 유틸리티에서 공용 도크 관리 계층으로 발전시키기 위한 작업 목록이다.

## P0 - 안정성 및 공용화 기반

- [ ] **공용 모듈 설치와 로드 경로를 확정한다.**
  - 모든 도크 플러그인이 동일한 `herdr-dock-grid` 버전을 사용하도록 설치·업데이트 방식을 정한다.
  - 플러그인별 `dock_layout.py`, `herdr_api.py` 복사본은 호환 기간에만 유지하고, 제거 조건과 버전 호환 정책을 문서화한다.
  - GitHub 설치본에서도 공용 플러그인 경로를 안정적으로 찾는 방법을 확인한다.

- [x] **도크 상태 레지스트리를 만든다.**
  - 플러그인이 `plugin_id`, 제목, 기본 위치, 최소 크기, 콘텐츠 진입점을 선언해 등록하도록 한다.
  - 레지스트리에 workspace ID, pane ID, 레이아웃 버전, 마지막 확인 시각을 저장한다.
  - 재시작 시 등록 정보와 실제 `herdr pane list` 결과를 대조해 사라진 pane과 오래된 상태를 정리한다.

- [x] **점유 처리의 경쟁 조건을 제거한다.**
  - 현재의 빈 `*.dock` marker와 대기 시간 기반 순서 제어를 원자적 잠금 또는 단일 상태 갱신 방식으로 교체한다.
  - 동시 실행, 실행 중 강제 종료, marker 파일 손상 시나리오에서 중복 pane 할당이 없어야 한다.
  - pane ID가 현재 도크 워크스페이스에 속하는지 검증한 뒤에만 점유 상태로 인정한다.

- [x] **도크 수명주기 API를 정의한다.**
  - `register`, `ensure`, `release`, `reconcile`의 책임과 오류 처리를 명확히 한다.
  - 플러그인 종료·비활성화 때 pane과 상태를 정리하는 규칙을 정한다.
  - 사용 중인 pane, sidebar pane, 다른 플러그인 pane은 정리 과정에서 절대 변경하지 않는다.

## P1 - 레이아웃 관리

- [x] **고정 2x2 규칙을 레이아웃 정책으로 분리한다.**
  - 현재 `DOCK_ORDER`와 split 순서를 코드 상수에서 분리한다.
  - 기본 정책은 호환성을 위해 2x2를 유지하되, 등록 순서와 새 플러그인 추가가 복사본 수정 없이 가능해야 한다.
  - 지원 가능한 pane 수를 넘을 때의 동작을 명시한다. 예: 빈 pane 재사용, 새 행/열 생성, 사용자 확인.

- [ ] **레이아웃 저장·복원과 마이그레이션을 구현한다.**
  - [x] 현재 pane topology를 버전 관리 스냅샷으로 저장·조회한다.
  - [ ] 전체 레이아웃 setter가 제공되면 스냅샷 복원과 안전한 마이그레이션을 구현한다.
  - 워크스페이스별 레이아웃과 레이아웃 버전을 저장한다.
  - 버전 변경 시 기존 pane을 안전하게 이전하고, 실패하면 검증된 마지막 레이아웃으로 복원한다.
  - 사용자가 조정한 pane 위치와 크기를 기본 정책보다 우선한다.

- [x] **도크 조작 API를 추가한다.** (`list_docks`, `reset_dock_state`, `release_dock_pane`, `src/dock_cli.py`, herdr 액션 `list`/`reset`/`snapshot`)
  - `close`/`move`는 다른 플러그인 pane에 영향을 줄 수 있어 제외했다. 소유 플러그인이 자기 pane을 닫도록 `release_dock_pane`만 제공한다.
  - 플러그인과 UI가 사용할 열기, 닫기, 표시/숨김, 이동, 초기화 API를 제공한다.
  - API 호출 실패는 성공처럼 처리하지 말고 원인을 포함해 호출자에게 반환한다.

## P2 - 플러그인 이전 및 UX

- [ ] **기존 플러그인을 공용 등록 모델로 이전한다.**
  - 우선 `herdr-timekit`, `herdr-simple-git`, `herdr-talk`을 이전한다.
  - 이후 이전 방식이 다른 `radio`, `ai-feedbag`, `stockpulse`을 이전한다.
  - 각 플러그인에서 중복된 도크 배치·marker 관리 코드를 제거한다.

- [ ] **talk 도크 블록의 유지 정책을 결정한다.**
  - 10분 무활동 종료 후에도 도크 블록을 유지할지, 종료 시 닫을지를 결정한다.
  - 블록 클릭 시 대화창 포커스가 기대대로 동작하는지 실제 herdr에서 확인한다.

- [ ] **관리 UI 필요성을 검토한다.**
  - 등록된 도크 목록, 표시/숨김, 위치 초기화, 레이아웃 초기화를 최소 기능으로 검토한다.
  - UI는 공용 상태 레지스트리와 수명주기 API가 안정화된 뒤에 추가한다.

## 검증 기준

- [ ] 공용 모듈 설치본 사용과 fallback 경로 각각에서 도크 플러그인을 동시에 시작해도 pane이 겹치지 않는다.
- [ ] 플러그인 강제 종료와 herdr 재시작 후 오래된 점유 상태가 복구된다.
- [ ] 존재하지 않거나 다른 워크스페이스에 속한 pane ID는 재사용하지 않는다.
- [ ] 사용자 조정 레이아웃이 재시작과 레이아웃 마이그레이션 뒤에도 보존된다.
- [ ] 이전한 모든 플러그인이 기존 단위 테스트와 실제 `herdr plugin action invoke` 점검을 통과한다.
