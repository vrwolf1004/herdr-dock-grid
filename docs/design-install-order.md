# 설계 메모: 설치와 실행 순서

herdr-dock-grid 는 실행 프로세스가 없는 라이브러리다. 다른 플러그인이 이미 떠 있는 상태에서 나중에 설치되는 경우가 많다고 본다. 그래서 설치 순서와 상관없이 동작해야 한다.

## 전제
- 다른 플러그인은 ensure 때 `installed_plugin_path("herdr-dock-grid")`로 원본을 찾고, 없으면 자기 `src/dock_layout.py` 복사본을 쓴다.
- 이미 실행 중인 플러그인은 재시작 전까지 옛 복사본을 계속 쓴다. grid 설치로는 바뀌지 않는다.
- herdr 가 플러그인 startup 명령을 실행하는 순서는 보장되지 않는다고 가정한다.

## 원칙
1. **표시 파일(`<key>.dock`)이 정본이다.** 옛 복사본은 표시 파일만 읽고 쓰므로, grid 는 표시 파일을 계속 읽고 쓴다. 레지스트리(`herdr-dock-grid.json`)는 marker에서 재구성하는 보조 인덱스다. marker가 없거나 pane이 더는 유효하지 않으면 해당 레지스트리 항목도 제거한다.
2. **정리는 한 번이 아니라 필요할 때마다 한다.** 각 `ensure_dock_pane()`은 같은 잠금 안에서 marker와 실제 pane으로 레지스트리를 정리한 뒤 할당한다. 여러 번 실행해도 결과가 같아야 한다(idempotent). 그러면 설치 시점과 startup 순서에 기대지 않는다.
3. **startup 은 정확성에 쓰지 않는다.** grid 의 startup 을 두더라도 "먼저 실행돼야 맞는" 구조는 만들지 않는다. startup 은 정리를 미리 해 두는 편의일 뿐이다.
4. **레지스트리 쓰기는 `registry_lock` 으로 보호한다.** 여러 플러그인이 동시에 호출해도 충돌하지 않아야 한다.
5. **프로토콜 버전을 적는다.** 표시 파일이나 레지스트리에 버전을 남겨, 서로 다른 버전이 만나면 경고할 수 있게 한다.

## 운영 안내
- grid 를 설치한 뒤에는 이미 떠 있는 플러그인을 재시작해야 grid 원본을 쓴다.
- 재시작 전까지는 옛 복사본과 grid 가 같은 워크스페이스에서 함께 동작해야 한다. 원칙 1 이 이것을 보장한다.

## 미정 사항

- 레지스트리의 `version`을 프로토콜 버전으로 사용한다. legacy marker는 pane ID만 읽으므로 형식을 바꾸지 않는다.
- 옛 복사본이 버전 불일치를 감지했을 때 어떻게 할지(경고만 할지, 자리를 양보할지)

## 레이아웃 복원 결정

- `save_layout_snapshot()`은 현재 pane topology를 버전 관리된 레지스트리 스냅샷으로 저장한다.
- 현재 Herdr CLI에는 전체 topology를 원자적으로 적용하는 setter가 없다. 상대 `pane resize`만으로 복원하면 다른 플러그인 pane의 크기를 바꿀 수 있다.
- 따라서 전체 layout setter API가 제공될 때까지 자동 복원과 마이그레이션은 구현하지 않는다.
