# 설계: 여러 dock 워크스페이스 (herdr-dock2 이후)

워크스페이스당 4개 자리(`grid-2x2`)를 유지한다. 블록이 4개를 넘으면 다음 dock 워크스페이스를 만든다.
구현은 `src/dock_layout.py` 에서 한다. 이 문서는 구현 전에 동작과 경계를 정한다.

## 기본 규칙

1. **워크스페이스 이름**: 첫 번째는 `herdr-dock`, 두 번째는 `herdr-dock2`, 세 번째는 `herdr-dock3` ... 로 한다.
2. **한 워크스페이스의 최대 블록 수**: `LAYOUT_POLICIES[policy]["max_docks"]`(현재 4). 워크스페이스마다 따로 센다.
3. **배정 순서**: 플러그인은 자기 키로 `ensure_dock_pane(key, cwd)` 를 호출한다. 이미 배정된 키면 기존 pane 을 돌려준다. 새 키면 다음 순서로 찾는다.
   - 가장 앞선 dock 워크스페이스에 빈 자리가 있으면 거기에 둔다.
   - 없으면 다음 dock 워크스페이스(이미 있으면 그곳, 없으면 새로 만든다)에 둔다.
   - 모두 찼으면 새 워크스페이스를 만든다.
4. **레지스트리**: 항목의 `workspace_id` 가 배정된 워크스페이스다. 하나의 `herdr-dock-grid.json` 에서 모든 워크스페이스를 관리한다.
5. **표시 파일(`<key>.dock`)**: 형식을 바꾸지 않는다. pane id 로 구분되므로 워크스페이스가 달라도 된다.
6. **자리 계산**: 2x2 나누기는 워크스페이스 안에서만 한다. 다른 워크스페이스의 pane 은 건드리지 않는다.

## 함수별 변경

| 함수 | 변경 |
| --- | --- |
| `ensure_dock_pane(key, cwd)` | 여러 워크스페이스를 순서대로 보고, 필요하면 새 워크스페이스를 만든다. 반환값은 그대로 `(workspace_id, pane_id)` |
| `dock_workspace_id()` | 첫 번째 dock 워크스페이스를 돌려준다. 여러 개를 다루는 `dock_workspace_ids()` 를 추가한다 |
| `list_docks()` | 모든 dock 워크스페이스의 항목을 보여 준다. 워크스페이스 이름을 함께 표시한다 |
| `reconcile_dock_state()` | 모든 dock 워크스페이스의 live pane 을 기준으로 레지스트리를 맞춘다 |
| `reset_dock_state()` | 모든 dock 워크스페이스에서 죽은 항목을 지운다 |
| `release_dock_pane(key)` | 변경 없음. 워크스페이스는 건드리지 않는다 |

## 워크스페이스 정리

- 빈 `herdr-dockN` (N ≥ 2)은 `reset_dock_state()` 에서만 닫는다. 첫 번째 `herdr-dock` 은 빈 상태로 남긴다.
- `release_dock_pane` 에서는 정리하지 않는다. 플러그인 정지 중에 워크스페이스가 사라지면 다른 플러그인이 영향을 받기 때문이다.
- "빈" 워크스페이스는 모든 pane 이 라벨, 토큰, 에이전트, 배정 표시가 없는 상태다. 닫기 직전에 pane 목록을 다시 읽어 확인한다.

## 호환

- 옛 복사본(`src/dock_layout.py` 사본)은 워크스페이스 하나만 안다. 5번째 블록이 생기면 옛 복사본을 쓰는 플러그인은 `herdr-dock2` 를 모른다. 옛 복사본은 재시작 전까지 4개 안에서만 동작한다는 점을 운영 안내에 적는다.
- 새 원본을 설치한 뒤 재시작한 플러그인은 `herdr-dock2` 를 쓸 수 있다.
- 표시 파일 형식은 그대로라서 옛 복사본과 새 원본이 같은 마커를 공유한다.

## 테스트 계획

1. 단위: 워크스페이스 두 개를 가짜 목록으로 두고 배정 순서(첫 번째 빈 자리 → 두 번째 워크스페이스 → 새 워크스페이스)를 확인한다.
2. 단위: `list_docks` 와 `reconcile_dock_state` 가 여러 워크스페이스를 모두 보는지 확인한다.
3. 라이브: 블록을 5개 띄운다. `herdr-dock2` 가 생기고 5번째 블록이 거기에 뜨는지, 자리가 겹치지 않는지 확인한다.
4. 라이브: 5번째 블록을 정지한다. `herdr-dock2` 가 정리되는지 확인한다.
5. 라이브: `reset_dock_state` 를 실행해 죽은 항목이 지워지는지 확인한다.

## 구현 상태 (0.7.0)

구현 완료: `dock_workspaces()`, `dock_workspace_ids()`, 다중 워크스페이스 `ensure_dock_pane` / `list_docks` / `reconcile_dock_state` / `reset_dock_state`. 단위 테스트 4개 추가(총 18개). 라이브 확인은 `list` 만 했고, 5번째 블록 배정과 `herdr-dock2` 정리는 실제 플러그인 5개가 뜬 상태에서 아직 확인하지 않았다.

## 미정 사항

- 결정: 빈 `herdr-dock2` 는 `reset_dock_state` 에서만 닫는다. 이름 규칙은 `herdr-dock<N>` 이다.
- 옛 복사본이 5번째 블록을 만났을 때 경고를 띄울지 (미정)
